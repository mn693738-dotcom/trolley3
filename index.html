WebSocket connection

The status turns green only after the handshake succeeds.
🟢

Message format — send one JSON event per message. A JSON array of events is also accepted.

{"productId":"P001","productName":"Milk","price":30,"action":"add","quantity":1}

action is add or remove; quantity defaults to 1. Known IDs use the saved product name, price and picture. Unknown IDs are created from message data with a starting stock of 99 unless a valid stock is supplied. Invalid messages are ignored and logged.

Secure page note: Browsers block an insecure ws:// connection from an HTTPS page. Serve this dashboard over local HTTP on the Pi (or use secure wss:// with a valid certificate).

Run the dashboard on your Pi

Same local network, simple HTTP server
🍓

Save this file as index.html on your Raspberry Pi, then run:

python3 -m http.server 8000

Open http://<raspberrypi-ip>:8000 on a device on the same network. Then connect to ws://raspberrypi.local:8765.

Camera access: The simple HTTP server is fine for the WebSocket demo, but browsers block camera access on remote plain-HTTP pages. For camera tracking, open this page from localhost or serve it over https://.

Install the Python libraries with python3 -m pip install websockets gpiozero.

Settings & AI model

Configure billing, trolley camera zone, and custom product-model inference
Use a custom-trained product detector whose classes exactly match each product’s AI model class. Accepted inference response: JSON {"predictions":[{"x":320,"y":240,"width":100,"height":120,"class":"milk","confidence":0.92}]} with pixel-center box coordinates. Roboflow Hosted inference uses the model URL and an optional API key. The key stays in memory only, so re-enter it each session. Browser inference requests expose that key and upload cropped trolley frames to the configured endpoint; prefer a private backend proxy. Camera is drawn inside the blue trolley boundary; only zone-contained detections are considered. Default zone: left/top 15%, right 85%, bottom 90%.
